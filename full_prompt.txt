# 28. CENTRALIZED AI ENGINE

Create a reusable provider-independent AI engine.

Do not connect AI providers directly inside individual API routes.

Use a common provider adapter interface.

AI request workflow:

1. Identify the requested task.
2. Load active AI configuration from PostgreSQL.
3. Check user subscription permissions.
4. Check available credits.
5. Select the configured AI model.
6. Load credentials securely.
7. Build the appropriate task-specific prompt.
8. Execute the AI request.
9. Validate the response.
10. Handle provider failures.
11. Use fallback models when configured.
12. Record token usage.
13. Calculate estimated costs.
14. Deduct credits according to configured rules.
15. Save the result and usage logs.

Implement:
- Timeouts.
- Retries.
- Rate limiting.
- Error handling.
- Fallback providers.
- Structured JSON outputs.
- Response validation.

Never expose provider API keys to users.

Allow the admin to configure different AI models for different tasks.

4. Follow Python and TypeScript best practices.

6. Separate business logic from API routes.
7. Use proper database migrations.
8. Validate every API request.
9. Implement actual backend functionality.

13. Provide an example environment configuration.
14. Provide Docker configuration.
15. Document deployment steps.

18. Keep subscription permissions and AI configuration dynamic.

- Explain the implementation plan.
- Identify database changes.
- Identify backend endpoints.
- Identify frontend components.
- Implement the functionality.
- Run tests.
- Fix errors.
